## Matched low-question design

Use replicas 0 and 3 of run 39228730075 (unrotated and rotated/reflected, with their existing randomized IDs). Retain all six cases and both contracts. Each case forms a block of the same two original questions. Run each block once with full state and once with reduced state: two replicas x six blocks x two conditions x two questions = 48 question evaluations in 24 calls. Block order is shuffled and full-first/reduced-first is counterbalanced six times each. This keeps the previous question budget while increasing the number of small requests; token usage must be measured.

The fresh full baseline is necessary because the previous call contained twelve questions. Full and reduced in the present experiment always contain the same two questions, so their paired contrast does not confound question count with state size. Historical responses for these same 24 question instances are retained separately to expose batch/run drift.

## Projection rather than new explanation

Full state and all image assets are reconstructed exactly from the archived source input and frozen PNGs, with source request hashes checked before selecting questions. Full state contains four counterfactual snapshots. Reduced state keeps only the snapshot referenced by the two questions, then starts from all object IDs referenced in ALL five witness options and the query instructions. It follows object references to a fixed point: region vertex cycles and every boundary use, carrier IDs and endpoints, host polygons and points. The resulting object records are copied intact in their original relative order.

This preserves the wrong coincident carriers and region decoys as well as the correct candidate. No witness is privileged by the projection. Every retained region keeps its full original boundary-use array. Polygon cycles and coordinates stay because complete partition, adjacency and containment require geometry in addition to symbolic incidence. Unreferenced snapshots and unreachable objects are removed. The contracts, identity/evidence policies, option labels and ordering, object IDs, instructions and all original image bytes remain identical across each pair. No renaming, derived equality table, new binding facts, validity flags or oracle answer is added to state.

The independent checker must give the exact same failure-reason list for every proposed assignment before and after pruning, and enumerate the same existing graph bindings. In particular, omitted_valid must still have a real graph binding outside the offered assignments, and the distinct-material references must remain distinct. Tests verify reference closure, unchanged records, shared questions/assets, absence of gold leakage, reference-class counts and Actions guards.

## Outcomes and limits

Each condition has 24 questions: eight with a valid listed witness and sixteen requiring none. Always answering none gives 16/24 and is not success. Report positives, negatives, raw selected invalid witnesses, none, matrices by case/schema and exact paired changes. Counterfactual identity-pair success is reported per condition. Retain usage, native probability distributions/confidence, numeric reliability or null, timing, failures, all input hashes and images.

This intervention jointly removes competing snapshots and unused objects; it does not distinguish those contributions. The image assets remain unchanged and still include the original visual context. A failure after this reduction cannot rule out every context effect or prove that ID binding is intrinsically unavailable. Success would support sensitivity to state relevance in this exact task, not generalization to arbitrary graphs. There are only two transformed replicas and finite supplied witness options. Structured relations are supplied evidence; no autonomous visual extraction, theorem proof or internal sequential-reasoning claim follows.

Native answers are evaluated before any deterministic rejection. Do not repair counts using the checker. No native Score questions, automatic retries, threshold tuning or long-context header.
