# Triangle Multi-Agent Zero Discovery — Run 01

> First deliberately **banalized** triangle-network experiment under `MEROVINGIO_COGNITIVE_ARCHITECTURE_V03.md`.
>
> Goal: start from a theorem-like, weakly organized triangle network, inject disanalogies, route the resulting tensions to specialized cognitive agents, and test whether the network reorganizes itself toward a deeper family structure **without preloading `ISOSCELES`, `TRIANGLE_ZERO`, `ORDER_TRANSDUCER`, or any canonical-zero interpretation**.
>
> This is a conceptual/dry run of the multi-agent architecture. It is not yet an autonomous software execution. The experiment is written so that a later agent implementation can replay the same input blindly.

---

# 0. Experimental rule: hide the intended abstraction

The initial network may contain proposition-level facts, raw triangle roles, equality/order relations, and construction permissions.

It must **not** contain these concepts or labels:

```text
ISOSCELES
TRIANGLE_ZERO
CANONICAL_ZERO
OBJECT_ORDER_TRANSDUCER
F_OBJECT_ORDER
FIXED_POINT_OF_SWAP
INTERNALIZED_CONGRUENCE
```

The success criterion is structural, not terminological.

A run succeeds if the agents independently propose a family equivalent to:

```text
side_relation = opposite_angle_relation
stable states = {LT/LT, EQ/EQ, GT/GT}
```

and recognize that the middle equality state has a special organizing role under left/right role reversal.

Only after validation may the human-facing layer identify that emergent state with the classical isosceles triangle.

# 1. Banalized starting network N0

## 1.1 Material workspace

One generic triangle workspace exposes only four named roles:

```text
SIDE_L
SIDE_R
ANGLE_OPP_L
ANGLE_OPP_R
```

The reasoner may compare corresponding pairs qualitatively:

```text
SideRel  = rel(SIDE_L, SIDE_R)
AngleRel = rel(ANGLE_OPP_L, ANGLE_OPP_R)

Relation = { LT, EQ, GT, UNKNOWN }
```

No triangle subtype is predeclared.

## 1.2 Raw proposition modules

The initial graph knows only four proposition-like transformations:

```text
P5_RAW
    SideRel = EQ
        -> AngleRel = EQ

P6_RAW
    AngleRel = EQ
        -> SideRel = EQ

P18_RAW
    SideRel = GT
        -> AngleRel = GT

P19_RAW
    AngleRel = GT
        -> SideRel = GT
```

Role reversal licenses the mirrored `LT` forms, but these are not stored as a family.

The graph therefore initially looks theorem-centric:

```text
SIDE_EQ  -> ANGLE_EQ
ANGLE_EQ -> SIDE_EQ
SIDE_GT  -> ANGLE_GT
ANGLE_GT -> SIDE_GT

+ mirrored LT routes
```

Crucially there is no node saying these routes belong to one deeper structure.

## 1.3 Banalized pair/congruence packet

To create additional pressure on the network, the graph also knows three unrelated congruence access rules at PAIR level:

```text
PAIR_SAS_RAW
    side_1 EQ
    side_2 EQ
    included_angle EQ
        -> pair_coincidence/congruence

PAIR_SSS_RAW
    side_1 EQ
    side_2 EQ
    side_3 EQ
        -> pair_coincidence/congruence

PAIR_ASA_RAW
    angle_1 EQ
    carrier_side EQ
    angle_2 EQ
        -> pair_coincidence/congruence
```

At N0 these are merely separate criteria. There is no relation between them and the OBJECT-level triangle rules.

# 2. Initial network deficiencies

The experiment intentionally begins with the following representational weaknesses:

```text
D1. equality and order rules are stored separately;
D2. converse directions are separate proposition edges;
D3. GT and LT cases are duplicates under role swap but not compiled;
D4. identical stabilized states reached from different disanalogy seeds are not grouped;
D5. no family organizes {LT, EQ, GT};
D6. no state is marked canonical;
D7. pair-level congruence and object-level internal correspondence are unrelated;
D8. no reasoner-level explanation exists for why the four object propositions form one packet.
```

These deficiencies are part of the test. A successful Reorganization Agent should detect at least some of them.

---

# 3. Disanalogy injection

The experiment injects counterfactual breaks around the equality states without telling the agents what family is expected.

## 3.1 Break side equality

```text
B_SIDE_GT:
    source fact: SideRel = EQ
    break:       SideRel = GT
    open:        AngleRel = UNKNOWN

B_SIDE_LT:
    source fact: SideRel = EQ
    break:       SideRel = LT
    open:        AngleRel = UNKNOWN
```

## 3.2 Break angle equality

```text
B_ANGLE_GT:
    source fact: AngleRel = EQ
    break:       AngleRel = GT
    open:        SideRel = UNKNOWN

B_ANGLE_LT:
    source fact: AngleRel = EQ
    break:       AngleRel = LT
    open:        SideRel = UNKNOWN
```

Each event is stored with a `BreakSignature`, preserving which register was broken first.

---

# 4. Impetus field generated by the breaks

The raw breaks produce several simultaneous cognitive pressures.

```text
COMPLETION_IMPETUS
    an open relation remains after each break

GENEALOGICAL_IMPETUS
    side-origin and angle-origin runs may converge on identical final states

COMPRESSION_IMPETUS
    P5/P6 and P18/P19 repeatedly appear as converse pairs

REORGANIZATION_IMPETUS
    the theorem-centric graph duplicates one apparent schema across EQ/GT/LT

EXPANSION_IMPETUS
    ask whether other stable states exist beyond individually listed proposition cases
```

The Impetus Router sends the same events to different agents rather than selecting one global strategy.

# 5. Round 1 — Completion Agent

The Completion Agent is conservative. It does not introduce new concepts.

It simply runs licensed transformations.

## 5.1 Side-origin runs

```text
B_SIDE_GT
    SideRel = GT
    P18_RAW
        -> AngleRel = GT

result S1 = (GT, GT)
```

and by mirrored roles:

```text
B_SIDE_LT
    -> S2 = (LT, LT)
```

## 5.2 Angle-origin runs

```text
B_ANGLE_GT
    AngleRel = GT
    P19_RAW
        -> SideRel = GT

result S3 = (GT, GT)
```

and mirrored:

```text
B_ANGLE_LT
    -> S4 = (LT, LT)
```

## 5.3 Equality packet

The raw equality rules independently support:

```text
SideRel = EQ -> AngleRel = EQ
AngleRel = EQ -> SideRel = EQ

result S0 = (EQ, EQ)
```

Completion Agent output:

```text
observed stabilized states:
    (LT,LT)
    (EQ,EQ)
    (GT,GT)

observed mismatch candidates:
    (LT,EQ), (GT,EQ), (EQ,LT), (EQ,GT), ...
```

At this stage no family interpretation is allowed.

# 6. Round 1 — Genealogy Agent

The Genealogy Agent compares **how** identical final states were generated.

It finds:

```text
(GT,GT)
    genealogy A: break SIDE_EQ -> propagate to ANGLE
    genealogy B: break ANGLE_EQ -> propagate to SIDE

(LT,LT)
    genealogy A: break SIDE_EQ -> propagate to ANGLE
    genealogy B: break ANGLE_EQ -> propagate to SIDE

(EQ,EQ)
    route A: SIDE_EQ -> ANGLE_EQ
    route B: ANGLE_EQ -> SIDE_EQ
```

It therefore reports:

```text
STATE_IDENTITY != GENETIC_IDENTITY

but

MULTIPLE GENEALOGIES CONVERGE ON THE SAME THREE RELATIONAL STATES.
```

Proposal G1:

```text
The three stabilized states may belong to one latent generative family
rather than three unrelated theorem cases.
```

Status: `COGNITIVE_CANDIDATE`.

---

# 7. Round 1 — Compiler Agent

The Compiler Agent detects repetition across proposition routes.

Observed pattern:

```text
Relation in register X
    -> same qualitative relation in register Y

EQ -> EQ
GT -> GT
LT -> LT
```

It proposes a provisional macro-schema:

```text
RELATION_PRESERVING_CORRESPONDENCE

SideRel R
    <->
AngleRel R

for observed R in {LT, EQ, GT}
```

This is not yet accepted as a family, because the Compiler Agent is not allowed to refactor ontology by itself.

Status: `PROPOSAL`.

# 8. Round 1 — Expansion Agent

The Expansion Agent asks what the current pattern predicts.

Given the three stabilized states, it explores the nine-state product:

```text
{LT,EQ,GT} x {LT,EQ,GT}
```

and marks:

```text
observed/stabilized:
    (LT,LT)
    (EQ,EQ)
    (GT,GT)

counterfactual/off-pattern:
    the six off-diagonal combinations
```

It proposes a variation axis:

```text
NEGATIVE DISANALOGY <-> ZERO DISANALOGY <-> POSITIVE DISANALOGY
```

but does not yet identify which state should be canonical.

Status: `COGNITIVE_CANDIDATE`.

---

# 9. Round 1 — Reorganization Agent

The Reorganization Agent receives four signals:

```text
1. repeated converse proposition pairs;
2. same-sign stable states across three qualitative relations;
3. multiple genealogies converging on each stable state;
4. six off-diagonal states behaving as mismatch/counterfactual regions.
```

It judges the theorem-centric representation deficient.

Instead of adding more theorem edges, it proposes:

```text
REFACTOR_NETWORK
```

from:

```text
P5_RAW
P6_RAW
P18_RAW
P19_RAW
```

into a candidate family object:

```text
F_TRIANGLE_RELATION_CANDIDATE {
    registers:
        SIDE_RELATION
        OPPOSITE_ANGLE_RELATION

    stable_region:
        (LT,LT)
        (EQ,EQ)
        (GT,GT)

    counterfactual_region:
        six off-diagonal states

    allowed_variation_axis:
        LT <-> EQ <-> GT

    bidirectional_propagation:
        side relation <-> opposite-angle relation
}
```

This is the first major network restructuring.

# 10. Round 2 — symmetry pressure

The Generic Reasoner applies the existing role swap:

```text
sigma:
    LEFT <-> RIGHT
```

which induces:

```text
sigma(LT,LT) = (GT,GT)
sigma(GT,GT) = (LT,LT)
sigma(EQ,EQ) = (EQ,EQ)
```

This event is routed again.

## 10.1 Genealogy Agent result

The two oriented disanalogical states are one another's swapped variants.

The equality state alone is invariant.

## 10.2 Reorganization Agent result

It proposes enriching the candidate family with:

```text
symmetry:
    negative member <-> positive member

unique invariant member:
    equality/equality state
```

The agent does **not** use the words `isosceles`, `zero`, or `canonical`.

It reports instead:

```text
CENTRAL_INVARIANT_STATE_CANDIDATE = (EQ,EQ)
```

Reason:

```text
- it lies between the two oriented variants;
- it is fixed by role reversal;
- both registers lose disanalogy there;
- both converse equality rules close there;
- both oriented families can be generated as breaks away from it.
```

This is the crucial discovery event.

# 11. Round 2 — Validator

The Validator checks the proposed refactor.

## 11.1 Geometric support

```text
(EQ,EQ)
    supported by P5_RAW/P6_RAW

(GT,GT)
    supported by P18_RAW/P19_RAW

(LT,LT)
    supported by mirrored role versions
```

## 11.2 No target leakage

The emergent family was not supplied with:

```text
ISOSCELES
TRIANGLE_ZERO
FIXED_POINT
```

The fixed-member property follows from the explicit left/right swap operation.

## 11.3 Status

```text
F_TRIANGLE_RELATION_CANDIDATE
    -> VALIDATED COGNITIVE FAMILY
```

The validator certifies the internal organization of the family; it does not claim that `canonicality` is a Euclidean theorem.

# 12. Human-facing interpretation after validation

Only now may the semantic layer observe that:

```text
SideRel = EQ
AngleRel = EQ
```

is precisely the relational state classically instantiated by an **isosceles triangle** with respect to the selected side/angle roles.

Thus the experiment recovered, from a banalized theorem graph:

```text
           (LT,LT)
              \
               \
           (EQ,EQ)
               /
              /
           (GT,GT)
```

with `(EQ,EQ)` as the unique role-swap invariant state.

Human label:

```text
ISOSCELES = ZERO/FIXED MEMBER OF THE DISCOVERED TRIANGLE RELATION FAMILY
```

The word `zero` is justified cognitively because both active disanalogy registers vanish there, not because zero was predeclared.

# 13. Does the run reach the deeper genealogy?

Partially yes.

The run independently reconstructs:

```text
1. one family instead of four isolated theorem edges;
2. the three-state LT/EQ/GT organization;
3. side-angle reciprocal propagation;
4. equality/equality as the unique swap-invariant member;
5. the oriented states as breaks away from that invariant member;
6. different genetic paths reaching the same family member.
```

This is already structurally equivalent to the intended `isosceles-as-triangle-zero` view.

However the run has **not yet** independently discovered:

```text
A. internalized congruence as the deeper explanation of the invariant state;
B. SAS/ASA/SSS as externalizations of internal triangle correspondences;
C. the family-level relation between object-zero and pair-congruence-zero.
```

Those remain genuine next tests rather than being inserted into this run.

# 14. Pair-level pressure: deliberately unresolved probe

The three raw congruence criteria are now shown to the agents only **after** the object-family refactor.

The relevant question is not:

```text
"Which criterion proves the object family?"
```

but:

```text
"Does the newly discovered object-family organization make the
pair-level congruence packet look redundantly or incompletely represented?"
```

Signals to route in the next run:

```text
- equality as a zero-like condition appears in OBJECT and PAIR networks;
- pair criteria complete partial correspondences into global coincidence;
- object equality state contains two internal role correspondences;
- left/right role swap is already active in the object family;
- SAS/ASA/SSS expose different minimal masks over the same pair coincidence state.
```

Target concepts remain hidden:

```text
INTERNALIZED_CONGRUENCE
EXTERNALIZE
SELF_CONGRUENCE
```

A future run succeeds only if the agents themselves propose an appropriate cross-level restructuring.

# 16. Why this is a meaningful success

The important result is not that the system can be told that an isosceles triangle has equal sides and equal opposite angles.

The result is that a deliberately poor representation:

```text
P5 + P6 + P18 + P19
```

is unstable under disanalogy exploration.

Different specialized agents apply different pressures:

```text
Completion      -> fills open relations
Genealogy       -> notices convergent histories
Expansion       -> exposes the state-space
Compiler        -> notices repeated relation-preserving behavior
Reorganization  -> replaces theorem fragments with a family
Validator       -> certifies the refactor
```

and the network reorganizes toward a structure in which the equality/equality state becomes the unique symmetry-fixed center.

In the language of v0.3:

```text
A strong commonality did not merely add an edge.
It forced REFACTOR_NETWORK.
```
