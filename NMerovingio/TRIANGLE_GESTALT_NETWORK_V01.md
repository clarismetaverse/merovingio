# Triangle Gestalt Network v0.1

> Fresh formalization. This file is intentionally independent from the earlier NMerovingio v0 implementation and does **not** assume that the old symbolic reasoner is the correct architecture.

## 0. Goal

Build a cognitive-geometric network for Euclid Book I in which propositions are not stored only as theorem dependencies, but as transformations of **Gestalten** across three levels:

1. `OBJECT` — one geometric object/configuration;
2. `PAIR` — correspondence between two objects/configurations;
3. `FAMILY` — a governed space of canonical states, stable variants, disanalogies, symmetries, and rebase routes.

The first frozen domain is the **triangle network**. The next experiment will inject the Gestalten of the transversal/intersection workspace and measure how they retroactively modify the triangle network.

---

# 1. Core design principles

## 1.1 State identity is not genetic identity

Two Gestalten may have the same current geometric relations but different cognitive status because they were generated by different breaks.

```text
STATE_IDENTITY != GENETIC_IDENTITY
```

Example:

```text
(side >, angle >)
```

may arise from:

```text
BREAK_SIDE_EQUALITY(>) -> propagate to angle
```

or from:

```text
BREAK_ANGLE_EQUALITY(>) -> propagate to side
```

The final state is identical; the genealogy is not.

## 1.2 Canonicality is local to a Gestalt

A figure can be canonical in one family and peripheral in another.

`REBASE` changes the currently active ground without requiring the material figure to change.

## 1.3 Analogy/disanalogy is relational, not an intrinsic label

Do not mark an object simply as `ANALOG` or `DISANALOG`.

Use:

```text
Analog_G(X, Y)
Disanalog_G(X, Y; BreakSignature)
```

A figure can be disanalogical relative to the canonical member of a family while still being structurally analogous to another member generated by the same rule.

## 1.4 A proposition can change the network

A proposition is not only a proof result.

```text
P_n : (Network_before, Workspace) -> (ProofTrajectory, Network_after)
```

`Network_after` may contain:

- new Gestalten;
- new edges;
- compiled paths;
- backward enrichments;
- new family memberships;
- new rebase routes;
- a different inferential role for already-existing objects.

# 2. Primitive relation algebra

Use an oriented qualitative relation set:

```text
Relation = { LT, EQ, GT, UNKNOWN }
```

or symbolically:

```text
{ -, 0, +, ? }
```

Interpretation:

- `EQ / 0`: equality / zero disanalogy;
- `GT / +`: first role greater than second;
- `LT / -`: first role less than second;
- `UNKNOWN / ?`: not yet resolved.

The coarse analog/disanalog view is:

```text
ANALOGICAL_ZERO = EQ
DISANALOGICAL = {LT, GT}
```

but the oriented version must always remain recoverable.

# 3. Level 1 — OBJECT Gestalt

## 3.1 Isosceles/order workspace

Let triangle `ABC` be read through two opposed side roles and their opposed-angle roles.

Define:

```text
S = rel(side_left, side_right)
A = rel(opposite_angle_left, opposite_angle_right)
```

An object-state is:

```text
ObjectTriangleState = (S, A)
```

## 3.2 Coarse analog/disanalog square

```text
                         ANGLE
                    EQ            NEQ
              +-------------+-------------+
         EQ   |  CANONICAL  |   ANGLE     |
SIDE          |  ISOSCELES  |   BREAK     |
              +-------------+-------------+
        NEQ   |   SIDE      |  STABLE     |
              |   BREAK     |  DISANALOG  |
              +-------------+-------------+
```

The off-diagonal cells are counterfactual mismatch regions.

## 3.3 Oriented 3×3 field

After the side-angle order family is compiled, the stable region is the diagonal:

```text
                    ANGLE RELATION
                   LT      EQ      GT
              +-------+-------+-------+
         LT   |stable |   x   |   x   |
SIDE          +-------+-------+-------+
         EQ   |   x   | zero  |   x   |
              +-------+-------+-------+
         GT   |   x   |   x   |stable |
              +-------+-------+-------+
```

Formal family:

```text
F_OBJECT_ORDER = {(LT,LT), (EQ,EQ), (GT,GT)}
```

The isosceles state `(EQ, EQ)` is the **zero/fixed point** of the family.

## 3.4 Proposition roles at OBJECT level

```text
I.5   : side EQ  -> opposite-angle EQ
I.6   : angle EQ -> opposed-side EQ
I.18  : side GT  -> opposite-angle GT
I.19  : angle GT -> opposed-side GT
```

The `LT` cases are obtained by role swap/reflection.

These propositions compile one transducer:

```text
OBJECT_ORDER_TRANSDUCER
side_relation <-> opposite_angle_relation
```

## 3.5 Swap symmetry / fixed point

Let `sigma` exchange left/right roles.

```text
sigma(GT,GT) = (LT,LT)
sigma(LT,LT) = (GT,GT)
sigma(EQ,EQ) = (EQ,EQ)
```

Hence the isosceles is the structural fixed point:

```text
sigma(ISOSCELES_ZERO) = ISOSCELES_ZERO
```

# 4. Disanalogy origin and genealogy

## 4.1 DisanalogySeed

A disanalogy starts as an event, not merely as a final relation.

```text
DisanalogySeed {
    id
    source_gestalt_id
    source_level

    register
    roles

    canonical_relation
    introduced_relation
    orientation

    source_operator
    provenance
}
```

Example:

```text
DisanalogySeed {
    source_gestalt_id: ISOSCELES_ZERO
    source_level: OBJECT
    register: SIDE
    roles: [SIDE_LEFT, SIDE_RIGHT]
    canonical_relation: EQ
    introduced_relation: NEQ
    orientation: GT
    source_operator: BREAK
}
```

## 4.2 BreakSignature

A normalized grouping key:

```text
BreakSignature {
    ground_family
    ground_gestalt
    level
    register
    role_pair
    relation_before
    relation_after
    orientation
}
```

This allows grouping all descendants of, for example:

```text
BREAK(ISOSCELES, ANGLE_EQUALITY)
BREAK(ISOSCELES, SIDE_EQUALITY)
BREAK(PAIR_CONGRUENCE, PLACEMENT_IDENTITY)
```

## 4.3 Origin status of a disanalogy

```text
DisanalogyOrigin = {
    SEED,
    PROPAGATED,
    RESIDUAL,
    REBASED
}
```

Example:

```text
SIDE GT     [SEED]
   |
   | PROPAGATE
   v
ANGLE GT    [PROPAGATED]
```

and conversely:

```text
ANGLE GT    [SEED]
   |
   | PROPAGATE
   v
SIDE GT     [PROPAGATED]
```

## 4.4 Disanalogy families

Define:

```text
D(B) = all Gestalten descended from BreakSignature B
```

Examples:

```text
D_BREAK_SIDE_EQUALITY
D_BREAK_ANGLE_EQUALITY
D_BREAK_PLACEMENT_IDENTITY
```

Each family can be queried coarsely or by orientation.

# 5. Residues

A disanalogy may be materialized as an analogical core plus residue.

```text
X > Y  ==>  X = Y + R
```

Residue types:

```text
ResidueType = {
    METRIC,
    ANGULAR,
    PLACEMENT
}
```

Schema:

```text
Residue {
    id
    type
    source_break_signature
    host_gestalt
    carrier
    role_now
    origin_role
    orientation
    provenance
}
```

Critical distinction:

```text
role_now    = CANONICAL
origin_role = RESIDUE
```

must remain possible after `REBASE`.

# 6. Level 2 — PAIR Gestalt

## 6.1 Pair correspondence workspace

For two triangles `T1` and `T2`, fix two corresponding sides as the carrier:

```text
S1(T1) = S1(T2)
S2(T1) = S2(T2)
```

Then define:

```text
H = rel(included_angle_T1, included_angle_T2)
B = rel(third_side_T1, third_side_T2)
```

Pair-state:

```text
PairTriangleState = (H, B)
```

## 6.2 Pair analog/disanalog square

```text
                    THIRD SIDE
                    EQ            NEQ
              +-------------+-------------+
         EQ   | CONGRUENCE  | COUNTER-    |
INCLUDED      | ZERO        | FACTUAL     |
ANGLE         +-------------+-------------+
        NEQ   | COUNTER-    | STABLE      |
              | FACTUAL     | DISANALOG   |
              +-------------+-------------+
```

## 6.3 Oriented pair field

Stable region:

```text
F_PAIR_ORDER = {(LT,LT), (EQ,EQ), (GT,GT)}
```

This yields a second transducer:

```text
PAIR_ORDER_TRANSDUCER
included_angle_relation <-> third_side_relation
```

## 6.4 Proposition roles at PAIR level

With two corresponding sides fixed:

```text
I.4   : included-angle EQ -> third-side EQ     [SAS direction]
I.8   : third-side EQ     -> included-angle EQ [SSS direction]
I.24  : included-angle GT -> third-side GT
I.25  : third-side GT     -> included-angle GT
```

The `LT` cases are symmetric counterparts.

## 6.5 Structural homology OBJECT <-> PAIR

```text
OBJECT LEVEL
side relation <-> opposite-angle relation
zero = isosceles
ordered cases = oriented scalene family

PAIR LEVEL
included-angle relation <-> third-side relation
zero = congruent pair
ordered cases = oriented dis-congruent pair family
```

Mapping:

```text
I.5  <-> I.4
I.6  <-> I.8
I.18 <-> I.24
I.19 <-> I.25
```

This is not a claim of proof dependence. It is a candidate **Gestalt-structural homology**.

# 7. Congruence as zero-state completion

Pair congruence should not be represented as one theorem node.

Represent a full pair correspondence vector:

```text
PairCorrespondenceVector {
    side_1_relation
    side_2_relation
    side_3_relation

    angle_1_relation
    angle_2_relation
    angle_3_relation

    placement_relation
}
```

A criterion of congruence is a **minimal zero-mask** sufficient to compile the remaining correspondence.

## 7.1 SAS mask

```text
SAS_ZERO_MASK = {
    side_1 = EQ,
    side_2 = EQ,
    included_angle = EQ
}
```

## 7.2 SSS mask

```text
SSS_ZERO_MASK = {
    side_1 = EQ,
    side_2 = EQ,
    side_3 = EQ
}
```

## 7.3 ASA mask

```text
ASA_ZERO_MASK = {
    angle_1 = EQ,
    angle_2 = EQ,
    included/carrier_side = EQ
}
```

General rule:

```text
sufficient_zero_mask -> FULL_CONGRUENCE_GESTALT
```

SAS, SSS, and ASA are therefore three different access routes to the same pair zero-state.

# 8. Placement register and I.7

The pair square is not sufficient: pair-space has at least one additional register.

```text
PLACEMENT = { ZERO, NONZERO, UNKNOWN }
```

Interpretation:

```text
ZERO    = corresponding vertices/closures coincide under the active overlay
NONZERO = a placement residue remains
```

I.7 is modeled as a rigidity test in which metric correspondence is preserved while a nonzero placement residue is hypothesized.

Schematic state:

```text
metric_residue    = ZERO
placement_residue = NONZERO
```

I.7 eliminates that state in its licensed workspace.

I.8 may then compile the zero-placement consequence into the SSS congruence view.

This register must remain distinct from ordinary metric or angular order.

---

# 9. ASA status before transversal injection

ASA is intentionally represented as a **compiled zero-view** but its disanalogical neighborhood is left open.

```text
ASA_ZERO_GESTALT = AVAILABLE
ASA_DISANALOG_NEIGHBORHOOD = OPEN
```

Do not pre-build the expected angular-order family around ASA before the transversal experiment.

Reason: the transversal/intersection network may introduce new angular carriers and retroactive shortcuts. We want to detect those rather than encode them in advance.

# 10. Level 3 — FAMILY Gestalt

A family is not a taxonomy class. It is a governed generative space.

```text
GestaltFamily {
    id
    level

    canonical_state
    role_schema

    stable_region
    counterfactual_region

    symmetries
    variation_axes

    inference_packet
    rebase_routes

    member_gestalts
    provenance
}
```

Examples:

```text
F_OBJECT_ORDER
canonical = (EQ,EQ)
stable = {(LT,LT),(EQ,EQ),(GT,GT)}

F_PAIR_ORDER
canonical = (EQ,EQ)
stable = {(LT,LT),(EQ,EQ),(GT,GT)}
```

A family groups figures by **shared generative grammar**, not simply by shape.

# 11. Cross-level operators

## 11.1 EXTERNALIZE

Move an internal correspondence into pair-space.

```text
internal relation in one object
    ->
corresponding relation across two objects
```

Examples:

```text
internal side equality -> cross-triangle metric correspondence
internal angle equality -> cross-triangle angular correspondence
```

## 11.2 INTERNALIZE

Collapse an external correspondence into one object/self-correspondence.

Example:

```text
pair congruence under role-swap -> isosceles self-correspondence
```

## 11.3 FAMILY_LIFT

Promote a stabilized object/pair pattern into a governed family with canonical state, stable variants, and symmetry.

## 11.4 INSTANTIATE

Select a concrete member of a family.

# 12. REBASE

`REBASE` changes the active inferential ground while preserving genealogy.

```text
REBASE(G, x) :
    x peripheral/residual in G
        ->
    x canonical/ground in G'
```

Required types:

```text
HORIZONTAL_REBASE
    same level, same family, different active canonical member

VERTICAL_REBASE
    reinterpret current structure as a member/substructure of a richer Gestalt family

CROSS_LEVEL_REBASE
    OBJECT <-> PAIR <-> FAMILY
```

Important invariant:

```text
origin_role must never be erased by role_now
```

## 13.2 COMPILE

```text

```

```text

    ->
```

# 14. Epistemic contacts

```text

    role
    provenance
```


```text

    -> PROPAGATED BREAK / COLLISION / STABILIZATION
```

# 20. Next experiment — transversal injection

The next phase must be performed **after** freezing this file as the baseline.

Build an independent transversal/intersection network containing, at minimum:

```text
INTERSECTION
VERTICAL_ANGLE_OPPOSITION
SUPPLEMENTARITY
STRAIGHT_ANGLE
COLLINEARITY
HALFPLANE / SIDE-OF-LINE
DISTRIBUTED_INTERSECTION
TRANSVERSAL_CARRIER
```

Possible later derived Gestalten may include parallelism, but they must not be pre-injected unless justified by the experiment stage.

Define:

```text
N0 = TRIANGLENET_0_1
T  = TRANSVERSAL_NETWORK
N1 = INJECT(N0, T)
```

Then measure:

```text
DeltaN = N1 - N0
```

Do not ask only:

```text
"Which new propositions are provable?"
```

Also ask:

```text
- Which old Gestalten gain new inferential roles?
- Which paths become shorter?
- Which counterfactual regions collapse?
- Which new cross-level analogies appear?
- Does ASA acquire a nontrivial disanalogical neighborhood?
- Do new REBASE routes appear?
- Do old triangle propositions become retroactively reinterpretable through transversal Gestalten?
- Does a previously peripheral angular carrier become canonical?
- Are new FAMILY-level homologies discovered?
```

The experiment is successful even if it produces **network restructuring** without immediately producing a new proof.

# 21. Research thesis encoded by this baseline

The working hypothesis is:

```text
Euclidean reasoning is not only theorem accumulation.
It is progressive reorganization of a network of Gestalten.
```

A later construction or proposition may retroactively change what an earlier object *is for reasoning*.

The triangle network is the first frozen test-bed for that claim.
